## 核心接口（确认后实施）

```java
// 元素定义：枚举 + 建造者，一个元素一行声明
public enum Element {
    PYRO  (Settings.create().color(0xFF5A3C).priority(2).aura(true)),
    HYDRO (Settings.create().color(0x3C8CFF).priority(2).aura(true)),
    ANEMO (Settings.create().color(0x5AE0C8).priority(2).aura(false)), // 风不作附着
    // ... 复合元素 BURNING/FREEZE/QUICKEN 带 linkTo(母体元素)
}

// 对外唯一入口：施加元素 → 内部处理 ICD → 附着税 → 触发反应
public final class ElementSystem {
    public static void applyElement(LivingEntity target, Element element,
                                    double gaugeUnits, String sourceTag, @Nullable LivingEntity origin);
}

// 反应：抽象基类 + 每反应一个子类
public abstract class ElementalReaction {
    abstract Element aura();       // 附着元素
    abstract Element trigger();    // 触发元素
    abstract double coefficient(); // 量值消耗系数
    boolean reversible() { return false; }
    abstract void onReact(LivingEntity target, double reducedGauge, @Nullable LivingEntity origin);
}
```

## 第六轮 spec：增幅反应接入伤害管线（18:36）

### 核心变更：元素命中的判定点从 hurtEnemy 前移到 LivingIncomingDamageEvent

原因：增幅反应要放大"当次攻击伤害"，必须在伤害结算前介入；hurtEnemy 是伤害结算后才触发的，位置不对。

### 新流程（法杖近战命中）

```
LivingIncomingDamageEvent
  └→ 直接近战命中 && 主手持元素法杖？
       ├→ ICD 检查（吞整次元素命中，伤害也不放大）
       ├→ 命中增幅反应（蒸发）？→ 消耗附着量值 → event.setAmount(伤害 × 倍率)
       │    → 余量按规则残留 → 结束
       └→ 否则 → 走 ElementSystem.applyElement 正常流程（剧变/控制/附着）
```

### 改动清单

- `ElementalReaction` 增加 Type（TRANSFORMATIVE / AMPLIFYING）；蒸发 = AMPLIFYING，onReact 只留粒子音效（伤害由管线放大）；超载/冻结 = TRANSFORMATIVE
- `ReactionRegistry.find()` 跳过增幅反应（applyElement 路径不应触发蒸发）；新增 `findAmplifying()`
- 新增 `logic/ElementalCombatHandler`：上述事件管线
- `ElementWandItem`：移除 hurtEnemy（不再在结算后施加），改为纯标记物 + element()/gauge() 访问器；给法杖 3 点攻击伤害属性让增幅效果可观
- `ElementSystem.applyElement` 拆出 skipIcd 内部变体（管线里 ICD 已判过，不能重复消耗）

### 行为变化（需告知用户）

- 蒸发只能在"法杖攻击命中带水/火附着的怪"时触发：伤害直接放大 1.5/2.0 倍
- 右键法杖自我附着不再触发蒸发（无伤害实例），属预期

## 第十二轮 spec：激化体系（19:26）

### 三个反应

- `QuickenReaction`（TRANSFORMATIVE 状态类）：草×雷双向 → 挂 QUICKEN 复合附着（量值=消耗量），无伤害
- `AggravateReaction`（超激化）：QUICKEN 附着 + 雷命中 → 当次伤害 +量值×2×1.15（加算）
- `SpreadReaction`（蔓激化）：QUICKEN 附着 + 草命中 → 当次伤害 +量值×2×1.2（加算）

### 框架改动

- `ElementalReaction.Type` 增加 ADDITIVE（加算反应，对应原神三类伤害反应：剧变/增幅/加算）
- 新增 `consumesAura()`（默认 true）：超激化/蔓激化**不消耗激化附着**（这是激化体系的玩法核心——状态存续期间持续受益）

## 第十三轮 spec：元素免疫规则（19:30）

- 用户决策：对某属性免伤的怪物挂不了对应属性附着（火免挂不了火等）
- 实现：`applyElement` 入口检查 `isImmuneToElement`：元素映射到原版伤害类型后用 `Entity#isInvulnerableTo` 判定
  - PYRO/BURNING → inFire（覆盖僵尸猪灵/烈焰人等原版火免）
  - CRYO/FREEZE → freeze（覆盖流浪者/北极熊/雪傀儡等原版冻免）

- 只挡"附着"，不挡反应：火免怪带水附着被火法杖打仍可蒸发（反应伤害归属触发方，与原神语义一致）
